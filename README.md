# Subtitle Edit 4.0.14 — Swoterd 修改版

基于 [Subtitle Edit](https://github.com/SubtitleEdit/subtitleedit) 4.0.14 的个人修改版，主要调整双字幕翻译、波形时间轴编辑和视频预览。

本分支为 `se4-custom`。修改源码整理日期：2026-11-21。原项目的版权声明与 GPL v3 许可证均予以保留。

**开发说明：本修改工程 100% 由 GPT 开发。** 本分支在原版基础上的新增功能、问题修复、构建脚本与说明文档均由 GPT 编写；维护者负责提出需求与实际使用验证。Subtitle Edit 原版基础代码的作者与贡献者见上游项目，原有版权归属保持不变。

## 主要修改

- 翻译模式支持打开原始字幕时按主字幕对齐时间轴，两份文件分别显示未保存状态。
- 修正原始字幕首次编辑的撤销记录，减少编辑、插入、删除、合并及撤销时的列表闪烁。
- 波形和频谱支持相邻字幕边界吸附，保留双字幕配对；一次拖动可一步撤销。
- 双字幕预览可分别设置样式，编辑后刷新当前画面；MPC-HC 字幕覆盖区域使用黑色背景。
- 打开主字幕、原始字幕、视频及各项导入操作分别记忆目录。
- 调整字幕合并、自动分割和歌词操作，并提供文本框右键对话合并命令。

完整说明见 [changelog.md](changelog.md)。

## 新增设置与默认值

以下为未加载旧配置时的代码默认值；已有配置会保留用户保存的选项。双字幕预览另有打开原始字幕时自动启用的行为，见表中说明。

| 设置项 | 位置 | 默认状态或数值 | 作用与说明 |
| --- | --- | --- | --- |
| 打开原始字幕后按主字幕对齐字幕轴 | 设置 → 常规 → 杂项 | **关闭** | 打开原始字幕时，将可一一配对的原始字幕起止时间对齐到主字幕。需同时启用原有的「允许编辑原始字幕」。对齐产生的实际修改可撤销，并需保存原始字幕。 |
| 合并两行时用换行符隔开 | 设置 → 常规 → 规则 | **关闭** | 关闭时普通合并默认用空格连接；开启后用换行连接。 |
| 自动吸附相邻字幕边界 | 波形／频谱区上方 | **关闭** | 拖动时，使阈值范围内的相邻字幕边界吸附并联动；翻译模式会保留配对并同步另一轨的时间调整。 |
| 吸附阈值 | 波形／频谱区上方，与吸附开关同行 | **100 毫秒** | 可设为 **0–2000 毫秒**，在启用自动吸附后生效。 |
| Aegisub模式：在频谱图显示视频关键帧/I帧 | 设置 → 波形/频谱图 → 频谱图 | **关闭** | 使用 ffprobe 提取视频关键帧，以粉色竖线显示。启用此模式后可按住中键拖动播放光标并吸附到视频帧。 |
| 翻译模式同时预览双字幕 | 设置 → 视频播放器 | **开启** | 主字幕显示在上、原始字幕显示在下。加载非空的原始字幕时，会自动启用此选项。 |
| 翻译预览设置：主字幕字体、字号、粗体与颜色 | 设置 → 视频播放器 → 翻译预览设置… | **Tahoma、12、粗体开启、白色** | 单独设置双字幕预览中的主字幕样式，与原始字幕及单字幕预览分别保存。 |
| 翻译预览设置：原始字幕字体、字号、粗体与颜色 | 设置 → 视频播放器 → 翻译预览设置… | **Tahoma、12、粗体开启、白色** | 单独设置双字幕预览中的原始字幕样式。 |

独立记忆打开目录、分文件显示未保存星号、撤销与列表刷新修正、自动分割保护，以及右键菜单中的对话合并和「歌词」操作直接生效，没有额外启用开关。

## 构建

环境：Windows、Git、.NET SDK **6.0.412**、.NET Framework **4.8 Developer Pack**。首次还原依赖需要访问 NuGet。

克隆本分支后，在仓库根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build-custom.ps1
```

脚本从原有模板生成程序集信息，还原依赖并编译 WinForms 程序。输出位于 `src/ui/bin/Release/net48/SubtitleEdit.exe`。`global.json` 固定了使用的 .NET SDK 版本。

本仓库提供源码。个人设置、最近打开记录、编译输出和本地测试素材不作为本次修改提交。

## 当前限制

- 部分 M2TS 文件在跳转后开始播放时仍可能短暂无声，相关播放器处理仍需继续排查。
- 当前代码中 `UppercaseLetters` 和 `TagsInToggleCustomTags` 的部分默认字符串存在乱码，详见 changelog。
